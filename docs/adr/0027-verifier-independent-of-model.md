# AD-27 — Faithfulness is a property of the architecture

> Part of the TrialGuard architectural decision log ([index](../../README.md#architectural-decision-log)). Amendments are appended here rather than replacing what they correct.

## Decision

Faithfulness is a property of the architecture, not of Llama 3.3, and that is now measured rather than asserted. Every figure in this repo came from one model family across two hosts, so the claim that the deterministic verifier is model-independent rested on n=1. Re-run on SIGIR under prompt v4 across **six families from five vendors spanning 24B to 671B** (Llama 3.3 70B, Qwen2.5 72B, Mistral-Small 24B, Gemma-3 27B, gpt-oss-120b, DeepSeek-V3), the retry is significant on **all six**, from -34.6% (Gemma, p=0.0083) to -87.6% (gpt-oss, p=0.0000); the whole matrix cost $0.5210 and needed no code change, because Phase 8 had already made `(provider, model)` a value the system reads rather than an ambient fact about which library was imported. What moves is the amount of work the verifier does: the rate at which a model attempts a decisive verdict on a non-verbatim quote varies **8.1x** across the set (1.10% to 8.87%), while what reaches a user does not move at all, since `verify/grounding.py` forces every ungrounded decisive verdict to `unverifiable` on a code path that never learns which model produced the quote. The tradeoff is also visible and consistent: models sort into commit-more-cite-worse (Llama, Qwen, Gemma: abstention 58-61%, citation precision 0.911-0.967) and abstain-more-cite-better (Mistral, gpt-oss, DeepSeek: abstention 73-79%, precision 0.985-0.989), and **trial accuracy follows coverage rather than citation precision** -- Llama leads at 0.2584 with the second-worst citations, because a model abstaining on 79% of criteria cannot resolve enough of a trial to roll it up. So no model can be ranked on faithfulness alone, and the standing default is defensible on accuracy at mid-pack cost rather than on inertia. [`e2_findings.md`](../../data/reports/e2_findings.md)

## Alternatives considered

Re-running the verifier stress test per model (it is pure Python that never sees the model, so six runs would measure the same function six times -- the 51/51 catch rate is structural here, not an empirical claim per family); testing a frontier API model (breaks the single-host comparison and the price comparability, and is recorded as the untested case rather than quietly implied); ranking the families and adopting the best citation precision, which is gpt-oss-120b at 48% less coverage than the incumbent
